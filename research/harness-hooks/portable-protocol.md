## Portable Complier contract, without pretending inputs are universal

1. **One harness-specific decoder per version/surface.** Normalize a request `{harness, version, surface, session_key, turn_key?, call_key?, parent_key?, tool_name, tool_class, mcp_server?, proposed_args, cwd?, project_roots?, policy_revision, invocation_key}`. Keep the original raw event for audit. Do not invent missing keys: Claude/Codex offer `tool_use_id`, Cursor `conversation_id`/`generation_id` and `tool_use_id`, Goose `tool_call_id`, Cline `taskId`/`tool_call.id`, Kiro's inspected example has no call ID. Distinguish structured argument objects from Cursor's specialized MCP JSON string and Copilot's possible stringified `toolArgs`. [Claude input](https://code.claude.com/docs/en/hooks) · [Cursor schema](https://cursor.com/docs/hooks) · [Goose inputs](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/hooks.md) · [Copilot inputs](https://docs.github.com/en/copilot/reference/hooks-reference).
2. **Daemon transaction.** CEL maps tool name plus exact args and provenance to a CSP event; daemon checks and reserves against `(tenant, protected contract instance, session, policy revision)` with an atomic compare-and-swap/lock. Return `{decision: allow|deny|indeterminate, decision_id, invocation_key, policy_revision, agent_feedback, permitted_actions, reservation_id?}`. An indeterminate **must not silently become allow**: map it to a real native denial where supported; otherwise classify that deployment as non-enforcing. A denial records no CSP transition. An allow token is not proof of successful execution.
3. **Harness-specific encoder.** Translate to *that surface's* deny JSON or exit code; feed a concise reason and permissible alternatives to the agent, and preserve the original tool's harness connection/authentication. `ask` only where the host genuinely supports waiting for a user; it is not a deterministic unattended block. Avoid rewritten arguments unless the daemon evaluates and reserves the exact rewritten call, and the hook confirms what is actually dispatched.
4. **Commit semantics.** Define each CSP event as **attempt**, **dispatch**, or **successful completion**, not an ambiguous “tool used.” If attempt, commit at the pre-hook's accepted decision; if success, reserve at pre-hook then commit at correlated post-success, release/compensate on post-failure/cancellation, and reconcile missing terminal observations. A denied call must never advance. A failed call must not count as successful unless the contract deliberately models attempts. Prehooks do not establish actual side effects or rollback; posthooks cannot undo them. Record hook errors, restarts and unknown outcomes explicitly. Treat retried model calls with different args as new attempts, and dedupe actual re-delivery by genuine call ID when available. [Claude pre/post/batch events](https://code.claude.com/docs/en/hooks) · [Copilot post-failure events](https://docs.github.com/en/copilot/reference/hooks-reference).
5. **Lifecycle and ownership.** Start/resume/fork may need distinct instance operations; session-end hooks can be skipped on crash and must not be the sole cleanup authority. Create a durable daemon lease/TTL with explicit reconciliation and a separate parent/child mapping when observable. Protect managed hook configuration, executables and daemon socket; project-owned hooks are not resistant to project-editing agents. Bind the daemon to the local identity, and authorize each client instead of trusting arbitrary stdin session strings. Cloud sandboxes need an appropriately reachable policy service **in their trust domain**, not a fictional connection to laptop localhost.
