## Native contract dossiers: where the differences actually matter

**Claude Code.** Load merged hooks from managed policy, `~/.claude/settings.json`, project `.claude/settings.json`/`.local.json`, plugin `hooks/hooks.json`, and skill/subagent scopes; managed hooks cannot be disabled from ordinary settings. Command, HTTP, MCP-tool, prompt and agent handlers exist; for deterministic local policy use synchronous command or carefully configured HTTP, **not** `async:true`. Common input has `session_id`, `prompt_id`, `cwd`, `hook_event_name`, optional transcript/permission mode; `PreToolUse` adds `tool_name`, object `tool_input`, `tool_use_id`. It runs after arguments are formed and before tool processing, including built-in `Agent`, shell/file/web tools and MCP. A structured deny sends `permissionDecisionReason` to Claude; allow alone leaves ordinary permission rules, including managed denies, operative. Exit 2 blocks; ordinary nonzero, invalid JSON and timeout normally continue unless `onFailure:"block"` (requires **v2.1.295+**); defaults are 600 seconds for command/HTTP/MCP-tool handlers. All matching hooks can run before decisions merge; deny wins, but other hooks may already have side effects. `SessionStart.source` includes startup/resume/clear/compact/fork, while `SessionEnd` is not a reliable durability commit by itself. `PostToolUse` and `PostToolUseFailure` distinguish results, with `PostToolBatch` covering resolved parallel batches. `@` file references injected during prompt preparation and `EndConversation` evade `PreToolUse`; `FileChanged` occurs **after** a change. Protect definitions and executables even with managed policy. [Exact input, output, lifecycle, defaults and version gates](https://code.claude.com/docs/en/hooks); [combination/permission examples](https://code.claude.com/docs/en/hooks-guide).

**Codex CLI.** Do not implement against old `notify`: its source labels it `legacy_notify`, passes a finished-turn JSON as a final argv element and spawns without waiting. Current event hooks live in `.codex/hooks.json` or inline `config.toml`, project/user/managed/plugin scopes; project and changed local commands require trust, with a dangerous trust-bypass flag. Set `[features].hooks`; current reference describes command handlers, stdin JSON `session_id`, `cwd`, `hook_event_name`, model and `PreToolUse` `tool_name`, `tool_input`, `tool_use_id`, plus applicable `turn_id`/permission mode. A hook's `{ "hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}` or exit 2 blocks; `ask` and `continue:false` are **not** supported pre-tool decisions in the current implementation. `PermissionRequest` only runs where approval would be requested; it cannot replace all-call `PreToolUse`. Local shell/unified exec, patch and MCP are covered; hosted tools are not promised. Matching command hooks launch concurrently, so put session serialization in the daemon. Default timeout 600 seconds; ordinary hook failure is not a dependable fail-closed guarantee. `SessionEnd` is main thread, while subagents report parent `session_id` and separate agent identifiers. [Codex event reference](https://developers.openai.com/codex/hooks) · [legacy source](https://github.com/openai/codex/blob/27c05a52/codex-rs/hooks/src/legacy_notify.rs).

**Gemini CLI.** `hooks.BeforeTool` command groups have a matcher and optional `sequential`; common input includes `session_id`, `cwd`, `hook_event_name`, timestamp; pre-tool includes `tool_name`, object `tool_input`, and possibly `mcp_context`/`original_request_name`. Shell is `run_shell_command`; MCP tool names use `mcp_<server>_<tool>`. Exit 2/stderr blocks with agent-facing explanation; exit 0 plus `{"decision":"deny","reason":"…"}` also blocks; other nonzero generally warns and continues. `hookSpecificOutput.tool_input` can rewrite, so record the **executed** args, not only proposed args. Group default timeout 60,000 ms. `AfterTool`, `SessionStart`/`SessionEnd` and `BeforeToolSelection` serve different purposes. User/project/system/extension settings and `hooksConfig.enabled`/disabled controls matter: a user-owned project script is not an admin-enforced boundary. [Hook reference](https://geminicli.com/docs/hooks/reference/) · [configuration](https://geminicli.com/docs/reference/configuration/).

**Copilot CLI, VS Code, cloud.** Current shared runtime uses JSON `version:1`, `hooks.preToolUse`, command entry (`command`/`bash`/`powershell`, CLI-only shell-free `exec`/`args`) or supported HTTP; pre-tool input uses **camelCase** `sessionId,cwd,toolName,toolArgs` and outputs `permissionDecision`, `permissionDecisionReason`, optionally replacement `modifiedArgs`. Default command timeout 30 seconds. Crashes and nonzero including exit 2 deny, but timeout **falls through normal permissions**; HTTP network/timeout/non-2xx also fails open. CLI loads various user, repository, cross-tool and policy scopes; machine policy hooks resist ordinary disable settings. Cloud agent loads **only** cloned repo `.github/hooks/*.json`, supports a reduced event/handler subset and preapproves calls; it cannot call `127.0.0.1` on the developer laptop. VS Code's separately documented legacy Local `PreToolUse` instead uses snake_case `session_id,tool_name,tool_input,tool_use_id` and `hookSpecificOutput` with `updatedInput`; legacy exit 2 blocks, other nonzero warns/continues. Never mix these wire formats, and distinguish the cloud's `permissionRequest` absence from the CLI's. [GitHub reference, including cloud/failures](https://docs.github.com/en/copilot/reference/hooks-reference) · [VS Code reference](https://code.visualstudio.com/docs/agents/reference/hooks-reference).

**Cursor.** Project `.cursor/hooks.json` and user `~/.cursor/hooks.json` register version-1 JSON, command/prompt handlers, timeout, matcher and `failClosed` (false by default). Generic `preToolUse` has `tool_name`, object `tool_input`, `tool_use_id`, `cwd`, common `conversation_id` and `generation_id`; output uses `permission:"deny"`, `user_message`, `agent_message`, optionally `updated_input`. `permission:"ask"` is not currently enforced for generic `preToolUse`. Specialized `beforeMCPExecution` has `mcp_server_name`, name and **JSON-string** input; check server identity, not only tool name. Specialized shell/read and Tab hooks have different payloads. Invalid JSON/schema on permission hooks blocks, exit 2 blocks, but crash/other exit/timeout normally allows unless `failClosed:true`. Cloud supports generic `preToolUse` but omits sessionStart/sessionEnd, MCP-specialized and Tab hooks, skips initial read-only turns, and redacts certain HTTP MCP outcomes; generic deny, not successful input rewrite, is supported there. A local session identity can be `conversation_id`; subagent start has a parent conversation and `tool_call_id`. [Cursor event schemas and cloud table](https://cursor.com/docs/hooks).

**Windsurf/Cascade.** Merged system, user and workspace `.windsurf/hooks.json` levels run shell commands for event-specific reads, writes, terminal and MCP; input common fields `trajectory_id`, `execution_id`, timestamp, `agent_action_name`, and event-dependent `tool_info` (for shell, `command_line,cwd`). Exit 2/stderr prevents the relevant pre action, other exits normally allow; post actions cannot undo side effects. No single generic pre-every-tool gate is established: maintain class-specific adapters and test internal/nested tool pathways. System files require elevated modification; hooks do not execute in Restricted Mode. No authoritative timeout default/outcome was established in the inspected page. [Cascade hooks](https://docs.windsurf.com/windsurf/cascade/hooks).

**Cline, Goose, Kiro, Hermes.** Cline CLI executable `.cline/hooks/PreToolUse.sh` (or custom `--hooks-dir`) receives `hookName:"tool_call"`, `taskId`, roots, and `tool_call:{id,name,input}` and returns JSON `cancel:true` plus `errorMessage`; Extension's `.clinerules/hooks/PreToolUse` and enable-setting are distinct. Its `--yolo` disables hooks, and failure/timeout disposition remains unverified. [Cline actual examples](https://github.com/cline/cline/blob/main/sdk/examples/hooks/README.md). Goose plugin `hooks/hooks.json` matches `PreToolUse` by regex, receives `session_id`, `tool_name`, `tool_input`, `tool_call_id`, `working_dir`; exit 2 or JSON block denies; otherwise delivery errors, timeouts and malformed output default to allow unless **`on_failure:"block"`**. The awaited `PreToolUseResult` records allow/deny before execution, while `PostToolUse` is observation; default timeout 30 seconds. [Goose guide](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/hooks.md). Kiro `.kiro/hooks/*.json` `PreToolUse` has `session_id,cwd,tool_name,tool_input`; its command action says **any nonzero** blocks Pre Tool Use, stderr informs the agent, default timeout 60 seconds, but timeout outcome and complete per-call IDs are not documented. CLI V3 `SessionStart`/`SessionEnd` should not be generalized to 2.x or Web. [Trigger/payload](https://kiro.dev/docs/hooks/types/) · [action exits](https://kiro.dev/docs/hooks/actions/). Hermes `pre_tool_call` plugin/shell callbacks return `action:"block"`; callbacks run per built-in/plugin tool, timeout/exception block, and `post_tool_call` can observe blocked/error/success results. A 30-second default plugin callback timeout and suppression of hung callbacks are documented; per-session global ordering is not. [Hermes hooks](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks).

**Remaining product distinctions.** OpenCode V1 plugin input `{tool,sessionID,callID}`, mutable `{args}` and an exception can prevent execution; V2 typed `execute.before` uses a failing `Tool.Error` effect. Neither supplies a process exit-code protocol. [OpenCode plugins](https://opencode.ai/docs/plugins/) · [V2](https://opencode.ai/v2/docs/build/plugins/). Pi core's `tool_call` extension is a direct code-level gate; `pi-yaml-hooks` is an additional package, not core. [Pi extensions](https://pi.dev/docs/latest/extensions/) · [package](https://pi.dev/packages/pi-yaml-hooks). Roo's [WIP proposal](https://github.com/RooCodeInc/Roo-Code/pull/10785) and Continue CLI's [documentation-request issue](https://github.com/continuedev/continue/issues/11115) are leads for a versioned local source/behavior check, **not** evidence that every installation has an enterprise-ready gate. Continue IDE permission policy, Amazon Q context hooks and Aider scripting should remain in a separate non-interception category. [Continue permissions](https://docs.continue.dev/cli/tool-permissions) · [Amazon Q context hooks](https://docs.aws.amazon.com/amazonq/latest/qdeveloper-ug/command-line-context-hooks.html) · [Aider scripting](https://aider.chat/docs/scripting.html).
